# 自作機(Quadra)内製化に向けたハードウェア要件メモ

Go2-W の `RobotSpec`(`robots/go2w.py`)と observation 定義(`envs/wheel_legged_env.py`)から逆算した、内製化に必要なセンサ・モータ・制御系の洗い出し。詳細設計前のたたき台。

## 1. アクチュエータ(計16軸: 脚12 + 車輪4)

| 部位 | 数 | 必要スペック(Go2-W実測/推定値) | 備考 |
|---|---|---|---|
| 股関節(hip)・大腿(thigh) | 8 | トルク 23.7 N·m、速度 30.1 rad/s、Kp=25、Kd=0.5 | QDD(準直接駆動)型、減速比低め |
| 下腿(calf) | 4 | トルク 35.55 N·m、速度 20.07 rad/s | 追加1.5:1減速、ESTIMATE扱い(実機要確認) |
| 車輪 | 4 | トルク 23.7 N·m、速度 30.1 rad/s、速度制御、armature 0.005 | 半径0.086m、位置制御ではなく速度制御 |

各軸に必要な要素:
- BLDCモータ(アウターローター型、QDD向き)+ FOCモータドライバ(=インバータ、16個必要)
- デュアルエンコーダ(モータ側+出力側、磁気or光学)
- 減速機(calfのみ追加ギア、他は低減速比〜ダイレクトドライブ)
- 電流検出(シャント抵抗)→トルク/有効仕事(`joint_effort`)推定用

## 2. センサ(observation項目から逆算)

| Observation | 必要センサ | 実機での扱い |
|---|---|---|
| `base_ang_vel`, `projected_gravity` | IMU(ジャイロ+加速度計、6軸以上、200Hz級) | 必須、姿勢推定の核 |
| `joint_pos_rel`, `joint_vel_rel` | 各軸エンコーダ(16軸分) | 必須 |
| `wheel_contact`(criticのみ、特権情報) | 車輪への荷重/電流ベースの接地推定、またはロードセル | 実機では直接取得不可、状態推定器で代替 |
| `terrain_height_scan`(17×11グリッド) | 深度カメラ or LiDAR(前方下向き) | Unitree純正C++コントローラ未対応(`policy.cpp_unsupported`)。自作でobservation実装が必要 |
| `base_lin_vel`(criticのみ、特権情報) | 直接観測不可 | 車輪オドメトリ+IMU(+必要ならビジュアル/GPS)でEKF推定 |

## 3. 制御系アーキテクチャ(2階層)

| 階層 | 数 | 役割 | 周波数 |
|---|---|---|---|
| アクチュエータ内蔵ドライバ(インバータ/FOC基板) | 16 | BLDCモータの転流制御、エンコーダのローカル読み取り | 〜kHz〜数十kHz |
| 中央リアルタイム制御ボード | 1 | 全16軸への目標値配信(CAN/EtherCAT)、安全監視(E-stop、関節リミット) | 〜200Hz(物理ステップ相当) |
| オンボード推論用コンピュータ | 1 | ポリシー推論(ONNX)、IMU/地形スキャン処理、状態推定 | 〜50Hz(decimation周期) |

データフロー:
```
[推論コンピュータ] 50Hz: obs → ONNX推論 → action(16次元)
        │ (UART/SPI/内部CAN、遅くてよい)
[中央リアルタイム制御ボード] 200Hz: action → q*/dq* → Kp/KdでPD/速度制御
        │ (CAN FD / EtherCAT、低遅延必須)
[インバータ ×16] → BLDCモータ+エンコーダ
```

### 推論コンピュータ⇔制御ボードの接続方式(1枚のSoCに統合する場合)

- **ヘテロジニアスSoC**(STM32MP1, i.MX8M等): Cortex-A(推論)とCortex-M/R(制御)が同一チップ内。通信は配線不要、チップ内共有メモリ+割り込み(OpenAMP/RPMsg)。ただし制御コアの性能は控えめ。
- **SoM+別MCU**(Jetson Orin + STM32等): 推論用SoMにユーザアクセス可能なRTコアがないため、基板上の配線(UART/SPI/内蔵CAN)で別チップのMCUと接続。GPU搭載SoMを使えるため推論性能は高い。
- Quadra(地形スキャンの重い推論+16軸200Hz制御)は**SoM+別MCU構成(Jetson Orin系 + STM32、UART/CAN接続)**が現実的。

## 4. 電源・構造

- バッテリー+BMS: 16軸同時高負荷(最大23.7〜35.55N·m)に耐える瞬間放電能力
- フレーム/リンク: hip-thigh-calfの脚構造、ベースシャーシ
- 車輪: 半径0.086m、円筒形状、適切なゴムタイヤ摩擦係数(sim上は0.3〜1.2で振っている)
- 非常停止・転倒検知回路(IMU閾値ベース)

## 優先順位メモ

`RobotSpec` 1つにロボット固有情報をまとめ、自作機へ移してもRLロジックは変更しない設計(README参照)。そのためハードウェア側は**関節/車輪の角度・速度を指定どおりに追従できること**(PD制御性能とエンコーダ精度)が最優先。`terrain_height_scan`用センサとその実装はUnitree公式でも未対応のギャップ項目であり、内製化時に自前で用意する必要がある。
